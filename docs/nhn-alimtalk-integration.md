# NHN Cloud 알림톡 연결

2026-09-18: 계약 및 발신프로필 등록 완료(사용자 확인). 템플릿 준비 중. 발송 시간은 **한국 시간 오후 2시, 주말·공휴일 포함**으로 확정했다.

## 역할과 현재 구현

우리 서비스가 계약별 날짜와 발송 대상을 정하고, 자동 실행 장치가 오후 2시에 발송 코드를 실행한다. NHN Cloud는 승인된 템플릿으로 메시지를 전달하고 결과를 제공한다. 계약이 바뀌면 발송 직전 최신 상태를 확인할 수 있도록 장기 예약 발송 대신 해당일 즉시 요청을 사용할 계획이다.

- 완료: 계약 일정 DB, 고객 동기화 시 자동 계산/보류, 오후 2시 날짜→시각 변환.
- 이번 구현: 서버 전용 NHN v2.3 치환 발송·단건 결과 조회 어댑터. 승인된 테스트 번호·템플릿만 허용하고 기본 비활성화. HTTP/네트워크 오류는 결과 불명으로 반환하고 재시도하지 않는다.
- 아직 미연결: 자동 실행 장치, 일정 점유와 발송 시도 DB 기록, 세션/토큰 발급, 결과 반영, 운영 발송. 어댑터 파일 추가나 환경변수 입력만으로 자동 발송되지 않는다.
- 실제 NHN 요청/발송은 아직 하지 않았다. 단위 테스트는 가상 응답만 사용한다.

## 지금 할 일: 템플릿 등록

NHN 콘솔의 `Notification → KakaoTalk Bizmessage → 알림톡 → 템플릿 관리`에서 등록한 발신프로필을 선택한다. 아래는 **검토·등록용 초안**이며 승인된 템플릿이 아니다. 운영 문구를 확인한 뒤 등록·검수 요청한다. 카카오/NHN 심사 결과에 따라 수정할 수 있다.

| 내부 회차 | 제안 템플릿 코드 | 제안 이름 |
| --- | --- | --- |
| onboarding-d7 | hometo_d7_v1 | 입주 후 생활 확인 |
| monthly-first | hometo_first_v1 | 첫 달 생활 확인 |
| monthly | hometo_monthly_v1 | 정기 생활 확인 |
| monthly-renewal | hometo_renewal_v1 | 계약 종료 전 의사 확인 |

### 입주 7일

```text
[홈투게더] 입주 후 생활 확인

#{name}님, 홈투게더입니다.
입주 후 생활에 불편한 점이 있는지 확인하고자 안내드립니다.
아래 버튼에서 현재 생활 상태와 필요한 도움을 알려주세요.
남겨주신 내용은 운영 담당자가 확인합니다.
```

### 첫 달

```text
[홈투게더] 첫 달 생활 확인

#{name}님, 홈투게더입니다.
입주 첫 달의 생활 상태를 확인하고자 안내드립니다.
아래 버튼에서 생활 중 불편한 점이나 운영 담당자에게 전달할 내용을 알려주세요.
```

### 정기

```text
[홈투게더] 정기 생활 확인

#{name}님, 홈투게더입니다.
계약 기간 중 정기적인 생활 확인을 안내드립니다.
아래 버튼에서 현재 생활 상태와 필요한 도움을 알려주세요.
남겨주신 내용은 운영 담당자가 확인합니다.
```

### 재계약

```text
[홈투게더] 계약 종료 전 의사 확인

#{name}님, 홈투게더입니다.
현재 계약 종료를 앞두고 향후 거주 계획을 확인하고자 안내드립니다.
아래 버튼에서 계약 연장 또는 퇴실에 대한 의사와 전달할 내용을 알려주세요.
응답만으로 계약 연장이나 퇴실이 확정되지는 않으며, 담당자가 확인 후 안내드립니다.
```

네 템플릿 모두 웹 링크(WL) 버튼 이름은 `체크인 응답하기`로 제안한다. 모바일/PC 링크 초안:

```text
https://hometogether-checkin-web.vercel.app/c/#{token}
```

`name`은 고객 이름, `token`은 발송 회차에 발급된 비밀 접근 토큰이다. 템플릿 등록 시 실제 고객 토큰을 넣지 않는다. 최종 운영 도메인을 바꿀 경우 템플릿 링크도 다시 확인한다. 코드에서는 승인된 템플릿의 정확한 치환자 이름을 사용한다.

## 인증정보 준비

서버 환경변수 이름은 `.env.example`에 추가했다. 실제 값은 gitignored 환경 파일에만 입력하고 채팅/PR에 붙이지 않는다.

- `NHN_ALIMTALK_APP_KEY`, `NHN_ALIMTALK_SECRET_KEY`: NHN 콘솔 API 인증값.
- `NHN_ALIMTALK_SENDER_KEY`: 등록한 발신프로필 키.
- `NHN_ALIMTALK_APPROVED_TEMPLATE_CODES`: 실제 승인된 코드만 쉼표로 구분.
- `NHN_ALIMTALK_TEST_RECIPIENTS`: 사용자가 테스트 발송을 승인한 번호만 쉼표로 구분.
- `NHN_ALIMTALK_TEST_SEND_ENABLED=false`: 승인된 테스트 발송 실행 직전에만 활성화. Preview는 계속 비활성화.

환경변수는 서버 전용이다. 아직 Vercel에 NHN 키를 저장하거나 발송을 활성화하지 않았다. 발신프로필 등록 완료와 API 키 준비 여부는 별개다.

## 발송 흐름 연결 시 완료할 작업

1. 오후 2시 실행 장치 선정·연결. `scheduledDeliveryAt`은 KST 14:00을 UTC 05:00으로 변환하며, 자동 실행 자체는 수행하지 않는다. 실행 지연 허용 범위는 추가 확정한다.
2. 잠금 아래 고객상태/동기화/계약/예정일/기존 세션을 재확인하고 일정별 시도를 영구 저장한다. 이름·전화번호로 과거 응답을 추측 연결하지 않는다.
3. 세션과 접근 토큰을 같은 회차에 연결한다. 발송 요청/실제 수신/14일 만료 기준을 확정하고 실패 시 기존 토큰을 안전하게 재사용할 수 있는 저장 방식을 구현한다.
4. NHN 요청 전에 시도 ID를 저장한다. 요청 응답의 accepted는 전달 성공이 아니다. requestId와 recipientSeq를 저장한 뒤 단건 조회 결과로 전달 상태를 확인한다.
5. 타임아웃/응답 유실은 결과 불명으로 보류하고 콘솔/조회로 대조한다. 무조건 새 요청을 보내지 않는다. 공급자 중복 키의 유효 범위만으로 장기 중복 방지를 대체하지 않는다.
6. 승인된 테스트 번호로 발송 → 링크 → 제출 → 인증된 운영 화면의 고객/회차 매칭까지 확인한다. 이후 운영 발송을 별도로 활성화한다.

현재 어댑터는 문자 대체 발송을 명시적으로 끈다. 리마인더와 실패 자동 재발송 정책도 아직 미확정이다.
