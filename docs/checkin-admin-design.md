# 정기 체크인 운영자 화면 — 확정 설계

2026-09-08 사용자 결정 반영. 초기 첨부 설계 및 작업 프롬프트와 충돌하면 이 문서의 확정 사항을 우선한다.

## 범위와 현재 기준

- 로컬 main c9edd07에 BE-A~D 병합 완료. 기존 단위 테스트 기준 70개.
- 같은 레포·같은 Next.js 앱에 운영자 화면을 추가한다. 입주자 UI와 루트 레이아웃은 수정하지 않는다.
- 운영자 1명. 이메일 allowlist, 매직링크 로그인. 다중 권한·담당자·처리 메모 없음.
- `/admin/responses`: 응답 목록·상세·과거 이력·진행 기록·확인 표시.
- `/admin/stats`: 정기 회차 4종의 참여·완료·불만·관심 통계.
- 이벤트 회차는 조회·통계에서 제외하되 기존 코드는 유지한다.
- 고객 등록과 알림톡 발송은 별도 작업. 시연 데이터는 개발 DB에서만 만들고 운영 DB와 분리한다.
- 이번에는 운영자 긴급 알림을 만들지 않는다. 화면 확인 주기는 운영자가 정한다.

## 확정: 확인 상태는 수동

- 상세 열기, 첫 행 기본 선택, 목록 조회, 새로고침, 미리 불러오기는 어떤 확인 상태도 쓰지 않는다.
- 상세 버튼: 미확인일 때 `확인함으로 표시`, 확인 상태일 때 `확인 해제`.
- 수동 확인은 reviewed_at을 기록한다. 중복 요청은 현재 확인 시각을 유지한다.
- 확인 해제는 null로 변경한다. 다시 열어도 미확인 상태를 유지하며 다음 수동 확인 때 새 시각을 기록한다.
- 표현은 `확인함`으로 고정한다. 연락 완료·문제 해결을 의미하지 않는다.
- RPC만 호출하는 Server Action에서 운영자 인증을 재검증하고 revalidatePath를 호출한다.
- 정렬은 긴급 → 불만 있음 → 최신순. 확인 여부는 정렬에 영향을 주지 않는다.

## A1 응답 화면

- 응답 1건 = 목록 1행. ok도 포함한다. 왼쪽 목록과 오른쪽 상세로 구성한다.
- 목록: 미확인 점·긴급 배지·실명·매물·불만 태그·자유어 1줄·접수 시각. 전화번호는 상세에서만 노출한다.
- 미확인은 굵게, 확인함은 낮은 강조. 회차·불만 유무·확인 여부·기간 필터.
- 기본 기간 최근 30일, 접수일 기준. 요약의 불만 건수는 불만 있는 응답 수이며 불만 항목 수와 구분한다.
- 상세: 불만별 독립 블록, 참여자 정보, 제출 정보, 진행 기록, 관심, 과거 이력, 수동 확인 상태.
- 빈 자유어: `설명 없이 태그만 선택함`. 원문을 수정하거나 감정 분석하지 않는다.
- 긴급은 issue.tag=urgent로 판정한다. R1/R2는 표시하지 않는다.
- 긴급 칩 스텝 기록이 있고 미제출인 세션은 별도 구역에 `긴급 경로 진입 · 미제출`로 표시한다. 확정 신고와 합산하지 않는다.
- 반복 신고는 같은 사람·태그가 다시 나타난 사실이다. 미해결이라고 단정하지 않는다.

## A2 통계의 집계 계약

- 공유 캐시 없이 요청마다 조회. 목록은 접수일, 참여 통계는 최초 initial/sent 발송일로 코호트를 정한다.
- 취소·이벤트 제외. 세션 단위 지표에서 동일 세션의 중복 발송 행을 중복 집계하지 않는다.
- D: 해당 최초 발송 코호트. V: D 중 진행 기록 있음. C: D 중 응답 있음. I: C 중 outcome이 ok가 아님.
- 참여율 C/D, 진입률 V/D, 완주율 (C∩V)/V, 기록상 미완료율 (V에서 C 제외)/V.
- 진행 기록 없는 완료는 별도 건수로 표시하고 도달 이벤트를 추정해서 보충하지 않는다.
- 응답 기한이 남은 미완료와 기한이 지난 미완료를 구분한다. 만료는 answer_expires_at 기준.
- 분모 0은 `계산 불가`, 1~9는 `1/3`, 10 이상은 `% (분자/분모)`. 건수·시간은 비율이 아니므로 표본 수를 병기한다.
- 발송 기록이 없으면 발송 기반 통계를 계산 불가로 표시한다. 시연 결과를 운영 실적으로 대체하지 않는다.
- 불만 설명 확보율: 비어 있지 않은 free_text 불만 / 전체 불만 항목.
- 자유어 작성률: 완료자 중 시나리오상 자유어 답변(provided/skipped)이 있는 세션을 분모로, 하나 이상 provided인 세션을 분자로 한다. 미제출자의 작성 여부는 알 수 없다.
- 커뮤니티 K/C, K/E. 주제별 비율의 분모는 topics_submitted_at이 있는 세션(S). 다중선택 합계는 100%를 초과할 수 있다.
- 소요 시간은 유효한 최초 기록~제출 간격 30분 이하의 중앙값·p25·p75. 30분 초과는 별도 건수. 음수·기록 없음은 계산 제외 및 식별.
- 반복 신고는 동일 participant_id/tag의 두 번째 이후 응답 건수. 코호트 이전 이력도 반복 여부 판정에 참고한다.
- 리마인더 후 응답률은 리마인더 발송 성공 세션을 중복 제거하고, 최초 성공 리마인더 뒤 제출한 세션 수로 계산한다. 인과 효과라고 표현하지 않는다.
- 불만 태그 분포는 불만 항목 단위. 칩 분포는 태그 하위. 긴급률은 긴급 불만이 있는 완료 세션/C.
- 초기 긍정: onboardingStatus=ok, firstMonthStatus=ok, monthlyStatus=ok, renewalSupportStatus=none. 초기 긍정 완료 중 최종 불만 비율을 표시한다.
- 정기 4종 비교를 제공한다. 단일 선형 퍼널로 분기·스텝 생략을 이탈이라고 표현하지 않는다.

## 진행 기록과 라벨

- 시각은 서버에 기록된 reached_at이며 실제 답변 시각이 아니다. 누락·지연 가능성을 명시한다.
- 기록 없음은 `진행 기록 없음`. 마지막 기록 지점은 확정 이탈 지점이 아니다.
- 질문/선택지는 기존 시나리오, 칩은 domains/checkin의 getCheckinDetailOptions를 조회한다.
- 입주자 UI 컴포넌트는 공유하지 않지만 도메인 정의와 서버 시나리오 레지스트리 읽기 재사용은 허용한다.
- scenario_id/version에 맞게 해석한다. 미지원 버전은 임의로 최신 문구로 해석하지 않는다.
- ordinal을 원래 입력 순서로 해석하지 않는다. 자유어 길이는 해당 태그의 보존된 원문에서 계산한다.

## 구현 단계

1. AD-A: 검토용 SQL, 인증, 공통 레이아웃. 로그인·인증 완료는 공개 경로, 나머지는 Proxy와 서버 인증으로 보호.
2. AD-B: 응답 목록·상세·이력·긴급 미제출·수동 확인/해제.
3. AD-C: 시나리오 기반 진행 기록.
4. AD-D: 집계 함수 테스트 후 통계 화면 연결.

AD-A~AD-D는 feat/checkin-admin 브랜치 하나에서 진행한다. main에서 파일 변경·커밋은 금지한다. 작업 브랜치의 파일 변경·검증·커밋 및 필요한 브랜치 전환은 Codex가 수행할 수 있다. SQL 적용은 사람이 하며 푸시·PR 생성·병합·배포는 별도 요청이 필요하다.
