# 게스트 마스터 연동

## 2026-09-16 추가 확정 및 적용

- **계약정보가 완성된 고객만 신규 저장**, 미완성 고객은 시트에 두고 다음 동기화에서 다시 판단한다.
- 하루 한 번 자동 반영한다. 실행 코드는 추가했고 Apps Script 설치·권한 승인과 운영 배포가 남아 있다.
- 운영 DB `checkin_guest`에 완성 고객 5명 최초 저장 및 재조회 완료. 미완성 17명과 ID 전용 7행은 신규 저장하지 않았다.
- 중복 없는 게스트 ID→UUID 매핑, 특이사항 분리 저장, 기존 고객 정보 누락·행 삭제 시 삭제 대신 보류, 실행 기록과 접근 제한을 구현했다.
- 실행 명령, 실제 적용 상태, Apps Script 인증과 자동 실행 설정은 [고객 시트 동기화 설정](guest-sheet-sync.md)을 따른다. 아래 9월 8일 기록 중 저장/인증 설계가 미정이라는 내용은 이 결정으로 갱신됐다.

## 2026-09-08 확정

- 연동 대상은 홈투게더_고객데이터의 게스트_마스터 탭 하나다.
- 실제 고객정보와 특이사항 범주·상세를 저장하고 기존 체크인 응답 운영 화면과 연결한다.
- 실제 계약 시작일·실제 계약 종료일을 별도 열로 추가한다. 희망일·희망기간·메모에서 확정 날짜를 추정하지 않는다.
- 일정은 입주 7일 후, 1개월 후, 이후 매월 입주일 기준이다. 마지막 월간 예정일에는 일반 월간 대신 재계약 체크인을 보낸다. 종료 30일 전 별도 발송은 하지 않는다.
- 29~31일에 해당하는 날짜가 없는 달은 말일로 보정한다. 최초 연동 전 지난 회차는 소급 발송하지 않고 퇴실·계약 종료 고객의 신규 정기 발송은 제외한다. 사용자는 예외안 중 2번만 위 마지막 월간 대체 규칙으로 수정했다.
- 월간 예정일이 없는 초단기 계약과 첫 월간이 마지막 월간이기도 한 계약의 회차 우선순위는 추가 확인한다.

## 기존 구조와 연결 지점

- checkin_participant → checkin_session → checkin_response 관계와 토큰·14일 만료 규칙을 재사용한다.
- `checkin_guest`는 필수정보가 완성된 고객 원본이다. 미완성 신규 고객은 DB에 넣거나 가짜 날짜로 채우지 않는다.
- 외부 게스트ID와 내부 UUID 매핑은 구현했다. `checkin_participant.guest_id` 참조 경로를 마련했으며, 실제 계약별 참여자 생성·연결과 재계약 시 과거 계약 맥락 보존은 후속 작업이다.
- 특이사항 범주·상세는 설문 이슈와 별도 항목이며 운영자 인증 경로에서만 제공한다.
- `hometo_checkin`은 운영용, `hometogether-admin`의 체크인 테이블은 가상 테스트용이다. 실제 고객 5명은 운영용에만 입력했다. [환경 분리 진행 상태](test-environment.md)를 따른다.

## 구현 상태

- src/server/checkin/guest-import.ts: FORMATTED_VALUE 행을 헤더명으로 해석하는 서버 전용 순수 미리보기 함수.
- 원본 탭 X/Y열에 실제 계약 시작일·종료일 헤더와 날짜 표시/검증을 추가했다. 9월 16일 기준 5명의 확인된 계약 날짜가 입력돼 있다.
- 빈 행/ID만 있는 행 분리, ID 중복의 모든 행 표시, 전화번호 정규화, 실제 날짜 누락·오류·역전 검사.
- 미리보기와 DB 저장, 인증된 일일 동기화 경로를 연결했다. 미완성 신규 행은 저장하지 않는다. 저장 결과는 발송 승인 목록이 아니다.
- 실고객 값은 소스·테스트에 저장하지 않는다. 테스트는 가상 데이터만 사용한다.
