# 게스트 마스터 연동

## 2026-09-08 확정

- 연동 대상은 홈투게더_고객데이터의 게스트_마스터 탭 하나다.
- 실제 고객정보와 특이사항 범주·상세를 저장하고 기존 체크인 응답 운영 화면과 연결한다.
- 실제 계약 시작일·실제 계약 종료일을 별도 열로 추가한다. 희망일·희망기간·메모에서 확정 날짜를 추정하지 않는다.
- 일정은 입주 7일 후, 1개월 후, 이후 매월 입주일 기준이다. 마지막 월간 예정일에는 일반 월간 대신 재계약 체크인을 보낸다. 종료 30일 전 별도 발송은 하지 않는다.
- 29~31일에 해당하는 날짜가 없는 달은 말일로 보정한다. 최초 연동 전 지난 회차는 소급 발송하지 않고 퇴실·계약 종료 고객의 신규 정기 발송은 제외한다. 사용자는 예외안 중 2번만 위 마지막 월간 대체 규칙으로 수정했다.
- 월간 예정일이 없는 초단기 계약과 첫 월간이 마지막 월간이기도 한 계약의 회차 우선순위는 추가 확인한다.

## 기존 구조와 연결 지점

- checkin_participant → checkin_session → checkin_response 관계와 토큰·14일 만료 규칙을 재사용한다.
- 현재 participant는 전화번호와 계약 날짜가 NOT NULL이다. 불완전한 시트 고객을 이 테이블에 바로 넣거나 가짜 날짜로 채우지 않는다. 미완성 고객 저장 영역과 운영 참가자 승격 설계가 필요하다.
- 외부 게스트ID와 내부 UUID 매핑, 재계약 시 과거 계약 맥락 보존을 구현해야 한다.
- 특이사항 범주·상세는 설문 이슈와 별도 항목이며 운영자 인증 경로에서만 제공한다.
- 기존 개발 DB/Preview에 실고객을 입력하지 않는다. 운영 DB 선정과 연결은 남아 있다.

## 구현 상태

- src/server/checkin/guest-import.ts: FORMATTED_VALUE 행을 헤더명으로 해석하는 서버 전용 순수 미리보기 함수.
- 원본 탭 X/Y열에 실제 계약 시작일·종료일 헤더, 날짜 표시/검증과 입력 안내를 추가했다. 고객별 날짜 값은 확인 대기 상태로 비워 두었다. API로 헤더·서식·검증을 다시 확인했다.
- 빈 행/ID만 있는 행 분리, ID 중복의 모든 행 표시, 전화번호 정규화, 실제 날짜 누락·오류·역전 검사.
- 결과는 발송 승인 목록이 아니다. 오류 행도 검토를 위해 보존하며 아직 DB 저장/API/스케줄러와 연결하지 않았다.
- 실고객 값은 소스·테스트에 저장하지 않는다. 테스트는 가상 데이터만 사용한다.
